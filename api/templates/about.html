How it works

From a fault code to the manual line behind the answer

A technician standing at a drive needs the right row of a 600-page manual, and needs to trust it. Every step below exists for one of those two needs.

1

Read the manuals like a technician would

Each PDF is split by layout into paragraphs, headings and individual table rows, so a fault row stays one unit. Every piece keeps its page, its position on the page and the section it sits in.

2

Search three ways at once

Each method catches questions the others miss.

SemanticMatches meaning: "won't start" finds "no rotation".
KeywordMatches exact terms: parameter names and part numbers.
Fault codeAn exact lookup of codes like 2330 against the 377 codes the manuals define.
3

Fuse by rank, scope by product

The three ranked lists are merged with reciprocal rank fusion: a passage ranked high by several methods wins. If the question names one drive family, only that family's manuals are searched.

4

Answer only from what was found

The model first decides whether the passages actually answer the question. It then fills a fixed structure (meaning, causes, steps, tools, safety warning) where every line must cite a passage it was shown.

5

Check before showing

Code, not the model, removes any line citing a passage the model wasn't given, and any safety warning that isn't word for word from the manual. If nothing survives, you get "not found" and the nearest pages.

6

Show the evidence

Every page link opens the exact region of the manual page, cropped from a pre-rendered page image, so you can check the answer in seconds.

Known limits

  • One manual is a scan without a text layer and isn't searchable until OCR is added.
  • Wiring diagrams are indexed by their text labels only. Figure descriptions aren't generated yet.
  • Nameplate photo entry is designed but not shipped. Type the model or fault code for now.
  • Results are measured on 25 questions. See the Results page.
